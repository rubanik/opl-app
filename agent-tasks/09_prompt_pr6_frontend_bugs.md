# PR 6 — prompt для агента: frontend quick bugs

Ты работаешь в репозитории `opl-app`.

## Важно

Агент не запускает Docker/контейнеры. Команды для Docker только написать пользователю.

## Цель

Безопасные frontend bugfixes.

## Задачи

### 1. `OplList.jsx`

Проверь optimistic delete с Undo.

Требования:
- timer реального DELETE очищается только при Undo или unmount;
- смена фильтра, поиска, страницы или коллекции не должна отменять pending DELETE;
- если DELETE упал, элемент должен вернуться в список или пользователь должен увидеть ошибку.

### 2. `OplDetail.jsx`

Найди `.sort()` на массивах из state/props.

Замени:

```jsx
arr.sort(...)
```

на:

```jsx
[...arr].sort(...)
```

или заранее подготовленную переменную `sortedSteps`.

### 3. `CommentsDrawer.jsx`

- новые комментарии сверху;
- soft-deleted комментарий отображается как “Комментарий удалён”;
- edit/delete доступны только автору, если backend отдаёт author/current-user info.

## Ограничения

- Не меняй дизайн.
- Не переписывай компоненты полностью.
- Не добавляй новые библиотеки.
- Не запускай контейнер.

## Что агент может проверить локально

```bash
cd frontend
npm run build
```

Если build недоступен — честно указать.

## Ручные сценарии для пользователя

1. Удалить OPL и не нажать Undo — DELETE ушёл.
2. Удалить OPL, сменить фильтр — DELETE всё равно ушёл.
3. Undo отменяет DELETE.
4. Порядок шагов стабилен.
5. Новый комментарий появляется сверху.
