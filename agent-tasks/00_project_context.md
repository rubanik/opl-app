# OPL App — контекст для агентов

Репозиторий: `rubanik/opl-app`

Текущий стек:
- Backend: FastAPI + SQLAlchemy + PostgreSQL
- Frontend: React + MUI + Vite
- Инфраструктура: Docker Compose
- Основные сущности: OPL, Step, Photo, Tag, Collection, Comment, User

## Важное ограничение по запуску

Агент НЕ запускает Docker, контейнеры и `docker compose`.

Контейнеры запускает пользователь вручную на удалённом сервере.

Агент должен:
- менять код и документацию;
- запускать только безопасные локальные проверки, если они доступны в его окружении;
- не пытаться стартовать контейнеры;
- не писать “я проверил через docker compose”, если этого не делал;
- в финальном ответе дать пользователю команды, которые нужно выполнить вручную на сервере.

Формат финального ответа агента:
1. Что изменено.
2. Какие файлы изменены.
3. Какие локальные проверки выполнены.
4. Какие проверки НЕ выполнены, потому что контейнер запускает пользователь.
5. Команды для ручной проверки на сервере.
6. Риски/что проверить глазами.

## Общие ограничения

- Не менять публичные URL API без отдельного согласования.
- Не делать большой рефакторинг вместе с багфиксом.
- Одна задача = одна ветка = один небольшой PR.
- Не добавлять новые DDL-миграции в `main.py`.
- Все новые изменения схемы БД делать через Alembic.
- Docker-команды агент только предлагает пользователю, но сам не запускает.
