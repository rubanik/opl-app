## Контекст проекта

- backend: FastAPI + SQLAlchemy + PostgreSQL
- frontend: React + MUI + Vite
- docker-compose поднимает db/backend/frontend
- сущности: OPL, Step, Photo, Tag, Collection, Comment, User

## Зафиксируй целевые правила продукта

### Public read

- список OPL публичный;
- конкретная OPL публичная;
- PDF публичный;
- фото публичные;
- комментарии публично читаются;
- коллекции публично читаются.

### Authenticated write

- создавать/редактировать/удалять OPL может любой залогиненный пользователь;
- создавать коллекции может любой залогиненный пользователь;
- создавать теги может любой залогиненный пользователь;
- писать комментарии может любой залогиненный пользователь.

### Comments

- редактировать комментарий может только автор;
- удалять комментарий может только автор;
- удаление комментария soft delete;
- комментарии плоские;
- новые сверху.

### Collections

- коллекция = крупный space / группировка инструкций;
- OPL может быть в нескольких коллекциях;
- OPL не может быть без коллекции;
- коллекции видны всем;
- удаление коллекции удаляет только связи, сами OPL остаются;
- в контексте коллекции показывать глобальные теги + теги текущей коллекции.

### Photos

- новые фото хранятся в local storage;
- в БД храним metadata + storage key;
- старые binary `Photo.data` поддерживать только для совместимости.

## Технические правила

- одна задача = одна ветка = один небольшой PR;
- не менять публичные URL API без отдельного согласования;
- не добавлять бизнес-логику в routes, если она больше 20-30 строк;
- новую доменную логику выносить в services;
- новые изменения БД делать через Alembic;
- не добавлять новые DDL-миграции в `main.py`;
- write endpoints должны требовать auth;
- nested ресурсы должны проверять принадлежность parent_id: `comment.opl_id`, `step.opl_id`, `photo.step_id`;
- frontend не должен мутировать state/props напрямую, например `arr.sort()` без копии;
- агент не запускает Docker/контейнеры, а только пишет команды для пользователя.
