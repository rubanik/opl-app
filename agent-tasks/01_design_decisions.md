# Зафиксированные дизайн-решения

## Доступ

Без логина доступны:
- список всех OPL;
- конкретная OPL;
- PDF;
- фото;
- комментарии;
- коллекции.

Только залогиненный пользователь может:
- создавать OPL;
- редактировать OPL;
- удалять OPL;
- создавать коллекции;
- создавать теги;
- писать комментарии.

Пока нет ролей и админа.

## Удаление и редактирование OPL

Пока любой залогиненный пользователь может редактировать и удалять любую OPL.

## Коллекции

Коллекция — это крупный space / способ сгруппировать инструкции.

Правила:
- OPL может быть в нескольких коллекциях.
- OPL не может быть без коллекции.
- Коллекции видны всем.
- Удаление коллекции удаляет только связи, сами OPL остаются.
- Если удаление коллекции оставит OPL без коллекции, backend должен вернуть ошибку и не удалять коллекцию.

## Теги

Правила:
- Есть глобальные теги.
- Есть теги конкретной коллекции.
- Теги коллекции отдельны от глобальных.
- В контексте коллекции показываем глобальные теги + теги текущей коллекции.
- Collection-scoped tag нельзя привязать к OPL, которая не входит в эту коллекцию.

## Комментарии

Правила:
- Комментарии публично читаются.
- Писать комментарии может только залогиненный пользователь.
- Редактировать комментарий может только автор.
- Удалять комментарий может только автор.
- Админа пока нет.
- Комментарии плоские.
- Новые комментарии сверху.
- Удаление комментария — soft delete.

Soft delete:
- строка в БД не удаляется физически;
- выставляется `deleted_at` или `is_deleted`;
- исходный текст удалённого комментария не должен возвращаться публично;
- UI показывает “Комментарий удалён”.

## Фото

Правила:
- Новые фото храним в local storage.
- В БД храним metadata + storage key.
- Старый вариант `Photo.data` поддерживаем только для обратной совместимости.
