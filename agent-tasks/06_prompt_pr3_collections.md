# PR 3 — prompt для агента: collections

Ты работаешь в репозитории `opl-app`.

## Важно

Агент не запускает Docker/контейнеры. Команды для Docker только написать пользователю.

## Цель

Привести коллекции к целевому дизайну.

## Целевой дизайн

- коллекции публично видны всем;
- создавать коллекции может любой залогиненный пользователь;
- OPL может быть в нескольких коллекциях;
- OPL не может быть без коллекции;
- удаление коллекции удаляет только связи, сами OPL остаются.

## Важное правило

Если удаление коллекции оставит какие-то OPL без коллекций, backend должен вернуть 400 и не удалять коллекцию.

## Задачи

1. Проверь модели `Collection` и OPL-Collection link.
2. Создание OPL:
   - требует минимум одну `collection_id`;
   - если `collection_id` не существует, вернуть 400/404;
   - не создавать OPL частично, если одна из `collection_ids` невалидна.
3. Обновление связей OPL с коллекциями:
   - нельзя убрать последнюю коллекцию у OPL;
   - попытка оставить OPL без коллекций = 400.
4. Удаление коллекции:
   - OPL не удалять;
   - связи удалить;
   - если после удаления какие-то OPL останутся без коллекций, вернуть 400 и не удалять коллекцию.
5. `GET collections` публичный.
6. `GET OPL list` публичный:
   - с `collection_id` отдаёт OPL этой коллекции;
   - без `collection_id` отдаёт все OPL.

## Frontend

- При создании OPL пользователь должен выбрать минимум одну коллекцию.
- Если выбран collection context, использовать его как default collection.
- Не давать сохранить OPL без коллекции.

## Тесты

- нельзя создать OPL без коллекции;
- нельзя создать OPL с несуществующей коллекцией;
- можно создать OPL в двух коллекциях;
- нельзя удалить последнюю коллекцию из OPL;
- удаление коллекции не удаляет OPL;
- нельзя удалить коллекцию, если это оставит OPL без коллекции.

## Команды для пользователя на сервере

```bash
docker compose build
docker compose up -d
docker compose exec backend alembic upgrade head
docker compose exec backend pytest
```
