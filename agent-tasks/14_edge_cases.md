# Edge cases, которые важно проверить

## 1. OPL без коллекции

Плохой сценарий:
- OPL лежит только в Collection A.
- Пользователь удаляет Collection A.
- OPL остаётся без коллекции.

Целевое поведение:
- backend возвращает 400;
- коллекция не удаляется.

## 2. Collection tag не своей коллекции

Плохой сценарий:
- OPL лежит в Collection A.
- Tag создан в Collection B.
- Пользователь привязывает Tag B к OPL A.

Целевое поведение:
- backend возвращает 400.

## 3. Комментарий через неправильный `opl_id`

Плохой сценарий:
- `comment_id` принадлежит OPL A.
- пользователь вызывает `PATCH /opls/B/comments/comment_id`.

Целевое поведение:
- 404.

## 4. Soft-deleted comment

Плохой сценарий:
- комментарий soft-deleted;
- API всё ещё возвращает исходный `text`.

Целевое поведение:
- text скрыт;
- `is_deleted = true`;
- UI показывает “Комментарий удалён”.

## 5. Public read не должен стать public write

Плохой сценарий:
- GET публичный;
- случайно POST тоже стал публичным из-за optional auth.

Целевое поведение:
- все POST/PATCH/DELETE требуют `get_current_user`.

## 6. Агент не должен запускать контейнеры

Плохой сценарий:
- агент пишет, что выполнил `docker compose up`;
- на самом деле контейнеры запускает пользователь.

Целевое поведение:
- агент меняет код;
- агент даёт пользователю команды;
- пользователь запускает контейнеры на сервере;
- агент честно пишет, какие проверки не выполнял.
